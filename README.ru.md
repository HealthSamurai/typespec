# Typespec 1.0 — дизайн с чистого листа

> 🇬🇧 [English](README.md) · 🇷🇺 Русский
>
> Статус: **дизайн-документ**, кода пока нет. Учтены 4 независимых ревью и эксперименты в форке Typed Clojure ([niquola/typedclojure@ts-features](https://github.com/niquola/typedclojure/tree/ts-features)).

## 0. Принципы

1. **Ноль рантайма.** Typespec не меняет ни одного байта скомпилированного кода. Аннотации — это данные, которые компилятор пропускает.
2. **Один язык типов.** Одна и та же запись используется в `s/def`, в сигнатурах, в externs, в сообщениях об ошибках и в JSON. Что тайпчекер напечатал, то можно вставить в код.
3. **Ключ = тип.** Квалифицированный ключ `:patient/id` везде означает одно и то же: то, что сказано в `(s/def :patient/id ...)`. Это главная идея spec, и Typespec держится за неё.
4. **Сигнатуры на границах, вывод внутри.** Публичная функция имеет объявленную сигнатуру, тело выводится локально. Никакого вывода «через три вызова» — так в TS, и поэтому TS быстрый.
5. **Читаем исходник, а не загружаем.** Декларации берутся из текста файлов. Код проекта не исполняется (кроме макросов проекта, раздел 7).
6. **Честность.** Всё, что тайпчекер не доказал, видно: `Unknown`, `Any` с причиной, `cast`, externs. CI считает эти дыры.
7. **Агенты пишут, тайпчекер судит.** Разметка рассчитана на то, что её массово ставят LLM-агенты; человек читает дифф и ошибки.

## 1. Язык типов

Это **данные в стиле spec**: подмножество spec-форм плюс несколько форм `t/`. Такие формы не вычисляются, их читает только тайпчекер.

```clojure
string?  keyword?  boolean?  uuid?  inst?            ; базовые
int?     double?   number?                           ; int? = long-подобные, не любое число
nil?     any?      t/unknown  t/never                ; any? = явный отказ, unknown = «сузь сначала»
#{"active" "inactive"}  #{:get :post}                 ; union литералов
(s/nilable T)   (s/or :a A :b B)                     ; union
(s/keys :req [:patient/id] :opt [:patient/name])     ; мапа с квалиф. ключами (структурная)
(s/keys :req-un [:patient/id])                       ; неквалиф. ключ :id, тип — из :patient/id
(s/coll-of T :kind vector?)  (s/map-of K V)  (s/tuple A B)
(s/merge A B)                                        ; вход должен пройти оба = пересечение требований
(t/fn [A B :-> R])                                   ; функция
(t/exact (s/keys ...))                               ; без лишних ключей
(t/and A B)  (t/pick T :k ...)  (t/omit T :k ...)  (t/partial T)  (t/keys-of T)  (t/get T :k)
(t/class java.time.Instant)                          ; Java-класс
(t/atom T)  (t/chan T)                               ; изменяемые — инвариантны
```

Переменные типа объявляются **явно** в сигнатуре (раздел 3). В `s/def` они не нужны.

Правила, которые тайпчекер не прячет:

- `s/and` даёт тип первого компонента. Остальные предикаты считаются **refinement**, то есть документацией (`pos?`, регулярки), и статически не проверяются.
- Форма вне подмножества — ошибка `TSP9001 not a type`, а не молчаливый `Any`.
- Рекурсия разрешена: `(s/def :fhir/extension (s/keys :opt-un [:fhir/extension ...]))` — рекурсивный тип, не `Any`.

## 2. Откуда берутся типы

| Что | Источник | Где пишется |
|---|---|---|
| значение ключа `:ns/k` | `(s/def :ns/k T)` | рядом с доменом (`specs.clj`) |
| форма сущности | `(s/def ::patient (s/keys ...))` | там же |
| сигнатура публичной функции | `t/sig` в начале `defn` или `s/fdef` | у функции |
| сигнатура приватной функции | не нужна, выводится локально | — |
| локальные значения | вывод | — |
| чужие библиотеки | externs | `typespec/externs/` |

### 2.1 `t/sig` — сигнатура как данные

```clojure
(defn find-patient
  {:t/sig '[Ctx :patient/id :-> (s/nilable ::patient)]}
  [ctx id]
  ...)
```

Это обычная attr-map `defn`. Тип **цитирован**, поэтому компилятор просто сохраняет его в метаданных var и ничего не исполняет. Typespec читает её из исходника. Несколько арностей и перегрузки пишутся так:

```clojure
{:t/sig '([:fhir/id :-> (s/nilable :fhir/resource)]
          [:fhir/type :fhir/id :-> (s/nilable :fhir/resource)])}
```

`s/fdef` поддерживается так же, для кода, где он уже есть: тайпчекер читает форму `s/fdef` из исходника. Если у функции есть и `t/sig`, и `s/fdef`, они должны совпадать, иначе ошибка `TSP2790`.

Почему не `^{:t ...}` на параметрах: метаданные на map-форме параметра теряются при раскрытии `fn`, а мета на attr-map без цитаты вычисляется. Одна цитированная сигнатура на функцию — одно место, без исключений.

### 2.2 Деструктуризация — проверка, а не источник

Когда тип параметра объявлен, деструктуризация **проверяется** против него:

```clojure
(defn display-name
  {:t/sig '[::patient :-> string?]}
  [{:patient/keys [name birthDate]}]
;;                      ~~~~~~~~~ TSP2339: :patient/birthDate is not a key of ::patient.
;;                                Did you mean :patient/birth_date?
  name)
```

Когда тип не объявлен (приватная функция), деструктуризация задаёт **локальную нижнюю границу**: «этой функции нужны такие ключи». Она проверяется на вызовах **в том же ns** и дальше не распространяется:

```clojure
(defn- label [{:patient/keys [id name]}] (str id " " name))
;; выведено: [(s/keys :opt [:patient/id :patient/name]) :-> string?]
```

Квалифицированный ключ без `s/def` в strict-режиме даёт ошибку `TSP2304: no spec for :patient/birthDate`. Так опечатка ловится даже без объявленного типа.

Неквалифицированный ключ (`{:keys [id]}`) получает тип только из объявленного `s/keys :req-un`. Если объявления нет, тип `t/unknown`.

### 2.3 `:keys!` и прочие директивы Clojure 1.13

`:keys!`, `:req!`, `:select`, `:excess`, `:missing`, `:all` — это **код**: они меняют поведение (`req!` бросает исключение). Typespec не ставит и не убирает их сам. Если они уже в коде, Typespec их понимает:

| Директива | Тип |
|---|---|
| `:keys! [a]` | ключ обязателен на входе. Любой `!` на вложенном уровне делает обязательным и не-nil **весь путь** к нему (`req!` на nil бросает). Значение — тип spec, nil остаётся, если spec его допускает |
| `:keys [a]` | значение `T \| nil`; параметр с одними `:keys` имеет тип `Map \| nil` |
| `:or {a d}` | `T \| typeof(d)`, а явный `{:a nil}` даёт `nil`; `:or` на `!`-ключе — ошибка компиляции Clojure, Typespec её повторяет |
| `[a & :b :c]` | `:b :c` участвуют в проверках без привязки; в `:keys!` тоже обязательны |
| `:select s` | `(t/pick (merge defaults Arg) ks)` рекурсивно по вложенным формам; `\| nil` если Arg nilable; record → обычная мапа |
| `:excess e` | рекурсивный остаток: неупомянутые ключи плюс вложенные `{:k под-excess}`, `\| nil` |
| `:missing m` | `!`-ключи для вызывающего становятся необязательными; привязки `T \| nil`; после `(when-not m ...)` сужаются |
| `:all a` | `(merge defaults Arg)`, аргумент побеждает |
| `(selector f)` | одна директива → её тип; несколько → `{:select .. :excess ..}` без nil-значений |
| `[& {:keys! [a]}]` | обязательные именованные аргументы |

Таблица сверяется **дифференциальным тестом**: генератор строит случайные формы и значения и сравнивает предсказанный тип с результатом настоящего `destructure`. Версия Clojure фиксируется в конфиге: синтаксис 1.13 ещё альфа, `:defaults` уже убрали, `:req!` добавили позже.

Реализовано так: точные правила для функций, в которые раскрывается форма (`req!`, `get`, `select-keys`, `merge`, `dissoc`, `some-vals`), плюс синтаксическое правило для понятных сообщений. Если правило и раскрытие расходятся, это ошибка тайпчекера, её ловит тест.

## 3. Система типов

- **Мапы структурные.** `(s/keys :req [:a])` принимает мапу с любыми другими ключами. **Чтение** ключа, которого нет ни в типе, ни в реестре spec, — ошибка (TS2339). Чтение у `nil` даёт `T | nil`.
- **Свежий литерал** `{...}` в вызове проверяется на лишние ключи **только против объявленного типа**. Лишний квалифицированный ключ без `s/def` — ошибка; ключ, похожий на опечатку, — ошибка с Did you mean.
- **`t/exact`** запрещает лишние ключи везде.
- **Операции над мапами** типизируются точно: `assoc`, `dissoc`, `update`, `merge`, `select-keys`, `get-in`/`assoc-in`/`update-in` с литеральным путём, keyword как функция в `map`/`filter`.
- **Generics** с явными binders и ограничениями:
  ```clojure
  {:t/sig '(t/all [a (r :< :fhir/resource)] [(s/coll-of r) (t/fn [r :-> a]) :-> (s/coll-of a)])}
  ```
  Неизменяемые коллекции ковариантны, `atom`, `volatile`, массивы и каналы инвариантны.
- **Литералы**: `1` в `let` расширяется до `int?`, в позиции union-литерала остаётся литералом; `(t/const {...})` — аналог `as const`.
- **Сужение** после `if`/`when`/`cond`/`case`/`when-let`, `some?`/`nil?`/предикатов типов/`instance?`/`=` с литералом/`contains?` на мапе. Свои guard-функции бывают проверяемые (сужение выводится из тела) и доверенные `t/guard!` (идут в отчёт).
- **Полнота**: `case` по union литералов, `cond`/`condp` по `=` над одной переменной, `defmulti` с закрытым dispatch (`{:t/closed true}`). `cond` без `:else` даёт `T | nil`, это не ошибка.
- **nil-punning**: `(first nil)` → `nil`, `(seq x)` сужает до непустой коллекции, `(:k x)` на `t/unknown` — ошибка «сузь сначала».
- **Строковые ключи** (JSON до keywordize): `(t/keys-str {"id" string?})`.
- **Хвост мапы**: `(t/keys {:req [...]} :rest (s/map-of keyword? any?))`.

### Clojure-специфика

| Конструкция | Правило |
|---|---|
| `defrecord R [a b]` | номинальный класс + поля + открытые лишние ключи; `assoc` сохраняет `R`, `dissoc` поля даёт мапу |
| `defprotocol` | `{:t/sig ...}` на методах; каждое `extend-*` проверяется, в том числе в чужом ns |
| `defmulti` | dispatch-функция типизирована; если она — keyword (`:resourceType`), в `defmethod` аргумент сужен по значению |
| `atom` | `(t/atom T)`; `swap!` требует `[T ... :-> T]`; сужение `@a` не переживает второй deref |
| `core.async` | `(t/chan T)`; `<!` → `T \| nil`; `go`/`go-loop` — встроенные правила |
| `binding`, `eval`, `resolve` | `t/unknown` |

## 4. Java и JVM-хинты

- `:tag` — это **компиляция**, а не тип Typespec. Хинт может стоять или не стоять, тайпчекер не требует хинтов и не ставит их сам.
- `^String x` тайпчекер понимает как `(t/class String)` **с nil**: компилятор nil не запрещает, и такого кода много. Не-nil дают только примитивы (`^long`) и сигнатура.
- Результат Java-метода по умолчанию — **платформенный тип**, как в Kotlin: nil не проверяется, но место попадает в coverage. `:strict-interop true` делает его `T | nil`. Аннотации `@Nullable`/`@NonNull` из байткода учитываются.
- Reflection — отдельное предупреждение `TSP7020`. Автофикс «добавить `^Class`» относится к категории `review`: он может изменить выбор Java-перегрузки.

## 5. Модули и скорость

Это то, что делает TS быстрым, и Typespec копирует это напрямую.

1. **Сигнатуры публичных var — интерфейс ns.** Ns `B` проверяется по **сигнатурам** `A`, а не по телам `A`. Правка тела функции в `A` не перепроверяет `B`.
2. **Strict требует сигнатур у публичных функций** (как `isolatedDeclarations` в TS 5.5). Тогда интерфейс ns вычисляется из текста одного файла, без проверки тел, и все ns проверяются **параллельно**.
3. **Кеш интерфейсов** — `.typespec/cache/<ns>.edn`, ключ — хеш исходника и интерфейсов зависимостей.
4. **Демон** (`typespec watch`, LSP) держит прогретую JVM и граф ns. Цель — <300 мс на сохранение файла среднего размера; это **бенчмарк в CI**, а не обещание.
5. **Генерация интерфейсов** для библиотек на Clojure: `typespec emit` выкладывает `.typespec/<lib>.edn` в jar, аналог `.d.ts`.

## 6. Чужие библиотеки — externs

```clojure
;; typespec/externs/next.jdbc@1.3.939.edn — только данные, не код
{next.jdbc/get-datasource ([string? :-> :next.jdbc/datasource]
                           [map? :-> :next.jdbc/datasource])
 next.jdbc/execute-one!   [:next.jdbc/datasource :next.jdbc/sql-params :-> (s/nilable :next.jdbc/row)]
 :types {:next.jdbc/datasource (t/opaque javax.sql.DataSource)
         :next.jdbc/sql-params (s/cat :sql string? :params (s/* any?))
         :next.jdbc/row        (s/map-of keyword? any?)}}
```

- Externs — **EDN**, а не Clojure. Они не загружаются, не исполняются и не попадают в рантайм.
- Версия в имени файла; если она не совпадает с `deps.edn`, будет предупреждение.
- Порядок поиска: свои externs → интерфейс, поставленный в jar библиотеки (`emit`) → `s/fdef` из исходников библиотеки → общий репозиторий `typespec-externs` → `t/unknown`.
- `typespec extern next.jdbc` — черновик от агента по arglists, docstring, исходнику и тестам. `--verify` прогоняет тесты библиотеки с `instrument` и проверкой `:ret`. Это **выборочная** проверка, не доказательство.

## 7. Как Typespec читает код

1. **Reader** — tools.reader с позициями и комментариями, без исполнения. Отсюда берутся `s/def`, `t/sig`, `s/fdef`, `ns`/`require`.
2. **Макросы core** (`let`, `fn`, `for`, `doseq`, `->`, `cond->`, `go`, `with-open` …) раскрываются **встроенными правилами** тайпчекера. Ошибки показываются в терминах исходной формы.
3. **Макросы проекта и библиотек** раскрываются в отдельном **рабочем процессе** без сети, проект в нём только на чтение. Загружаются только ns, где определены макросы, и их зависимости. Граница доверия: «макросы — доверенный код».
4. Макрос можно описать без раскрытия: `{:t/macro '[...]}` в externs, тогда тайпчекер в процесс не идёт.
5. Удалённый `s/def` исчезает из модели сразу, потому что реестра в памяти нет: есть только текст.

## 8. Подавление и доверие

```clojure
(t/ignore "AIDBOX-123: legacy" (legacy-call x))     ; макрос → просто (legacy-call x)
(t/cast ::patient row)                              ; → row
(t/any "dynamic plugin api")                        ; тип any? с причиной
```

`t/ignore`, `t/cast` и `t/any` — макросы-identity из крошечной runtime-библиотеки (около 20 строк, без зависимостей). Неиспользованный `ignore` даёт предупреждение (как `@ts-expect-error`).

**Бюджет доверия**: CI падает, если PR увеличил число `any`, `cast`, `ignore`, `guard!`, платформенных типов или ослабил тип. Ослабление — это `nilable`, удалённый `:req`, `:keys!` → `:keys`, сигнатура → `any?`.

## 10. Для агентов

```bash
typespec check src --json            # ошибки
typespec sig app.patients            # выведенные и объявленные сигнатуры ns
typespec type-at src/app/p.clj:14:9  # тип выражения (hover)
typespec annotate app.patients       # черновик t/sig и s/def — только данные, поведение не меняет
typespec fix --risk safe             # только безопасные автофиксы
typespec coverage --trust            # доказанное, дыры, бюджет
typespec order                       # порядок разметки: снизу вверх по графу ns
```

```json
{"version": 1, "id": "e3f1…", "code": "TSP2339", "severity": "error",
 "file": "src/app/patients.clj", "range": {"base": 1, "start": [14, 39], "end": [14, 48]},
 "file_sha": "9ac2…",
 "message": ":patient/birthDate is not a key of ::patient",
 "expected": "(s/keys :req [:patient/id] :opt [:patient/birth_date])",
 "actual": ":patient/birthDate",
 "cause_of": ["a91b…", "c02d…"],
 "related": [{"file": "src/app/specs.clj", "line": 7, "note": "::patient defined here"}],
 "fixes": [{"title": "Rename to :patient/birth_date", "risk": "safe",
            "edits": [{"range": {"start": [14, 39], "end": [14, 48]}, "text": "birth_date"}]}]}
```

- `expected`/`actual` печатаются **на языке типов из раздела 1**, их можно вставить в `t/sig`.
- `cause_of` группирует каскадные ошибки по первопричине. `id` стабилен между запусками (нужен для baseline).
- `risk` бывает `safe`, `review` или `unsafe`. Фикс через `any?`, cast или ослабление типа никогда не бывает `safe`.

**Источники для агента, в порядке доверия:**

1. FHIR Schema (генерация `s/def` для ресурсов Aidbox);
2. существующие spec и malli;
3. трассы тестов (записанные реальные значения → черновик);
4. код и docstring.

**Цикл агента:** `order` → `annotate` → `check --json` → правка типа или кода → повтор. Багфиксы и замены `:keys` → `:keys!` идут отдельным PR.
