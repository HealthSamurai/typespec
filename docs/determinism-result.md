# Воспроизводимость CLI: результаты после a2a86a2

## Реализовано и проверено

Метаданные стандартных функций теперь берутся из инертного versioned EDN-каталога, а не из состояния namespace в JVM. Восемь namespace; provenance Clojure1.12.4, spec.alpha0.5.238, core.specs.alpha0.4.74. Генерация из изолированного classpath этих трёх JAR документирована в ресурсе. При runtime нет require/resolve анализируемых зависимостей. Каталог проверяется на формат, происхождение и уникальность; отсутствие/повреждение не заменяется пустым каталогом.

Родитель независимо запустил:
- `clojure -M:test`: **124 теста /797 assertions**, все goldens, fresh/preloaded JVM, изменение live metadata и malicious core.async проходят.
- `bash examples/jar-declarations/verify.sh`: оба варианта bundled/split, runtime positive, static positive0 и negative TSP2345, библиотека не исполняется checker.
- В examples/context-web-pg: `clojure -M:check && clojure -M:test`: 0/0, trust0/0/0, unit3/22.
- `JAVA_HOME="$(/usr/libexec/java_home)" sh examples/context-pg-check/acceptance.sh`: Java27.0.1.1, exit0. Проверяются dependency pin, SHA полного исходника,451строка/54формы, точные коды/позиции обеих ошибок и восьми предупреждений, отсутствие загрузки pg и trust0/0/0. Старый диагностический launcher по-прежнему требует Java25 и возвращает exit1 при найденных ошибках; новый acceptance отличается тем, что ожидает эти ошибки.
- Мутационная проверка valid-resource?=true: усиленный тест ловит12 нарушений. Без мутации8тестов/71assertions PASS. Файлы валидатора не изменялись.

## Почему остаётся 8, а не ≤6 предупреждений pg

Это отдельная незавершённая цель, не следствие F2. С начала ночи11→8 за счёт source-backed контрактов; в текущем исправлении8→8.
- Строка30: неизвестный ключ строки до name; нужен контракт формы JDBC row или проверка ключа.
-49: динамический state не доказывает HikariDataSource; глобальный контракт state→Hikari был бы ложным.
-53,57,101: неизвестный ctx у connection/with-connection/execute!; локальная аннотация переносит требования на callers. Пробное расширение ранее давало21warning и требовало согласованных контрактов семейства API, callback и nullable результатов.
-115,117: неизвестный SQL до строковых операций в обработчике ошибки; нужен корректный контракт SQL и вызывающих функций.
-308: результат известен как String, но вызов остаётся reflective (TSP7023).

Обе ошибки сохраняются:57:15 TSP2322,206:41 TSP2345. Unknown/any/cast/ignore ради счётчика не добавлялись. Ниже порога не заявляем.

## Границы

Каталог фиксирован на указанных версиях, при обновлении нужна регенерация и тесты. Неизвестные namespace, включая core.async, не получают метаданные даже если пользователь их предзагрузил. Пропуск тел известных макросов остаётся старым ограничением; это не доказательство их типовой безопасности. Доверие к externs и startup user.clj остаётся как в night-report.md.

Независимое review Claude Fable5.2 завершено: [determinism-review.md](determinism-review.md). F2 закрыта, блокеров исправления нет. Fresh/warm/hostile JVM дали байт-в-байт одинаковый вывод; malicious core.async не исполнен, контроль ловушки сработал. Reviewer самостоятельно повторил suite124/797, проверил17 вариантов повреждения каталога и дубликат, регенерация совпала байт-в-байт. Примеры и pg acceptance независимо запускал родитель.

Остаются LOW: на другой версии Clojure (например1.13) новые vars, отсутствующие в каталоге1.12.4, могут ошибочно получить TSP2305; совместимость не заявляется без регенерации. Автотест повреждения каталога пока не перебирает каждое поле валидатора отдельно (reviewer проверил дополнительные случаи вручную).

Этот файл дополняет исторический night-report.md, а не переписывает его результаты задним числом. Исправление F2 принято, цель ≤6 предупреждений pg по-прежнему не достигнута по причинам выше.
