## Рабочие области

Изолированные worktrees `types`, `maps`, `diagnostics`, `externs` в `.hyper/tmp/cegl/implementation/`. Авторы не коммитят и не меняют общий runner/golden. Родитель переносит diff с контролем пересечений check.clj.

## Проверка

Каждая группа создаёт отдельный clojure.test namespace с regression cases. Перед принятием: targeted tests, общий suite, анализ новых диагностик, проверка согласованности CLI/JSON. Golden-файлы нельзя переписывать для скрытия регрессии. Ранее накопленные изменения документов не откатываются и не смешиваются с чужими worktrees.

## Границы

Не включены: полный generic solver, вся система macro hooks, version registry деклараций, экспорт jar, полный coverage, доказательство рекурсивного subtyping и soundness всего языка. При интеграции ограничение должно быть отражено в карточке, а не скрыто статусом implemented.

## Проверка и использование

`clojure -M:test`: 34 регрессионных теста / 239 assertions, плюс golden и CLI-проверки. Демо теперь содержит 33 диагностики (strict-nil: 39), README fixture — 6, examples — 11. Новые TSP210-01 сообщают о ранее молчаливых unknown-границах. Широкий legacy-ignore теперь поглощает такую диагностику и не считается unused; причина изменения эталона проверена отдельно.

```clojure
;; typespec.edn (EDN)
{:paths ["src"] :externs ["types/vendor.edn"]}
;; types/vendor.edn
{vendor.text/upper [string? :-> string?]}
```

Для явной замены встроенного core-контракта добавить `:externs-core :override`. По умолчанию конфликт запрещён. Никакого require/eval библиотеки. Missing type refs диагностируются, версия пакета пока не проверяется. Неизвестные границы совместимости — warning, `--strict` повышает их до error. JSON отдаёт reasons.

Новые диагностики: TSP210-01 — неполная проверка совместимости; TSP830-01 — некорректный ignore; TSP9003 — ошибка extern. Типовые причины неполноты: unknown, depth, unsupported-function.

Полный generic solver, SCC recursive subtype, автоматическая загрузка sidecars, jar exports и registry не реализованы. Compatibility engine сохраняет явный any как bypass. Неизменность старого количества ошибок не является целью: теперь ранее непроверенные места видны. Изменения не закоммичены и не отправлены.
