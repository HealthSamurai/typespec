## Что изменилось

Ресурсы читаются как inert EDN, только явно указанные локальные file/JAR, с проверкой отсутствия/неоднозначности/повреждения/конфликтов и происхождением classpath. Никакого автосканирования. Контракты truncate!, safe-execute!, fetch подтверждены исходником. Выигрыш 11→8 — три доверенных предусловия, не новый вывод типов. Fetch проверяет callback, включая nullable строку из JDBC; nil callback отклоняется.

Review обнаружил автозагрузку зависимостей ради метаданных. Она удалена, независимый repro больше не исполняет библиотеку. Тест закреплён в общем runner.

## Конкретные blockers и ограничения

1. **F2 MEDIUM: зависимость результата от состояния JVM.** Проверка метаданных использует только загруженные namespace. В свежем CLI может пропускаться TSP2305 для clojure.set/unionn, меняются диагностики clojure.test. Нужен фиксированный инертный каталог метаданных и сравнение fresh/warm JVM. Не возвращать небезопасный динамический require. Зелёный suite этого не решает.
2. **Порог ≤6:** оставшиеся предупреждения на30,49,53,57,101,115,117,308. Расширение контрактов connection/with-connection/execute! давало21 предупреждение, перенося проверки на вызывающие функции. Нужна согласованная разметка семейства API, callback и nullable результатов, а не unknown/any ради снижения счётчика. Подробности: night-pg-result.md.
3. Подключаемые extern-ресурсы доверенные: могут аннотировать функции проекта. Нет sandbox JVM (user.clj исполняется при старте Clojure), лимитов глубины EDN и автоматической проверки версий деклараций.
4. LOW F4: усилить assertions сообщений в тестах валидации путей. LOW F7: закрепить результат полного pinned pg отдельным автотестом; старый contracts.txt — исторический снимок.
5. Nullable Java hints не заменяют явную сигнатуру функции; найденный callback-кейс — существующее ограничение checker.
