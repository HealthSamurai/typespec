# Контракт минимального rank-1 solver

Статус: проект интеграции. Не утверждение о работающем generic solver.

## Первый срез

Явный `(t/all [a] [a :-> a])` в t/sig и extern. Параметрический identity должен независимо инстанцироваться для string и int; аннотированное тело проверяется для произвольного a, а не для первого вызова. Следующий обязательный сценарий — пользовательская HOF с inline fn, чей параметр получает ожидаемый тип.

## Представление

- `:all` содержит binder IDs, bounds и тело `:fn`.
- Имена binders служат печати, но сравнение использует идентичность/область видимости.
- Вызов создаёт свежие inference variables; проверка тела — rigid variables. Эти режимы нельзя смешивать.
- Подстановка обходит только типовые узлы и не захватывает переменные вложенных областей.
- Constraint хранит left/right, отношение совместимости, источник аргумента/результата и путь внутри типа.

## Процедура

1. Проверить грамматику t/all и уникальность binders; неизвестное имя не считать классом или any.
2. Выбрать поддержанную арность. В MVP одна декларация арности на generic-контракт; неоднозначные generic overloads — явное ограничение.
3. Собрать lower/upper bounds из аргументов и ожидаемого результата. Функциональные параметры обходятся с обратным направлением совместимости.
4. Сначала получить ограничения от обычных аргументов; затем передать уточнённый expected type inline callback. Нельзя повторно выпускать диагностики пробного inference.
5. Решать только ограниченное структурное подмножество: primitives, коллекции, функции фиксированной арности. Выбранные новые конструкции добавлять с отрицательными тестами.
6. Проверить подстановку против всех ограничений через sub-result. Неразрешённое, unknown, бюджет или unsupported не дают proved.
7. Вернуть substituted результат, substitutions и статус, отдельно от диагностики checker. Никаких побочных эффектов solver при переборе кандидатов.
8. Проверить generic-тело с rigid binders: вернуть число вместо произвольного a нельзя. Допустимые операции на a определяются bounds, не предполагаемым конкретным типом.

## Обязательные тесты

Identity с двумя независимыми типами; identity с неверным телом; повторный binder; неизвестный binder; ограничение a <: number и string-аргумент; callback с параметром из входной коллекции; callback с неверным результатом; scope/shadowing; unknown не решает a доказанно; зависимость результата от a сохраняется; отсутствие входных свидетельств не превращается в случайный тип.

## Не включено

Higher-rank, impredicativity, рекурсивные bounds, row inference, full protocol solver, general conditional types, универсальный comp/transducer inference. Ожидаемый тип — механизм проверки, не обещание вывести любую программу.

## Точки интеграции

`types/parse-type` и `show`: all/variables; `types/sub-result`: rigid compatibility. Новый `solver.clj`: instantiation/substitution/constraints. `check/call-fn`: generic path перед обычным вызовом. `check/check-defn`: rigid body check. `externs/load-contracts`: использовать общую грамматику generic signatures, не только parse-sig для вектора. `env`: не терять binder structure. Конкретные изменения уточняются по независимому review.

## Решение для первой реализации

Начать с одной generic-арности без rest/kwargs, bound по умолчанию unknown. В первом ядре явный bound — только primitive, например `(a :< number?)`; зависимые bounds и bounds-коллекции не поддерживаются. Поддерживать только rank-1 binders на верхнем уровне контракта. Вложенный all, зависимые bounds и неразрешённые переменные отвергать явно. IDs связывать со scope; имена нужны для show, не глобального равенства.

API solver должен быть чистым: `instantiate(all)` возвращает свежий fn и переменные; `constrain(state, actual, expected, origin)` накапливает обязательства; `solve(env, state)` возвращает status/substitution/issues; `substitute(type, substitution)` не меняет исходный тип. Допустимо объединить эти процедуры внутри одного публичного API, если тесты проверяют независимость вызовов. Не хранить изменяемый solver state в env глобально.

Проверку callback проводить после получения информации из обычных аргументов. Если параметр callback всё ещё не определён, не подставлять any: выдать incomplete либо запросить аннотацию. Для MVP не переанализировать callback многократно с побочными записями diagnostics/types.

Тело generic-функции открывать с rigid variables; операции над rigid проверять только по declared upper bound. Возврат конкретного типа вместо произвольного rigid-параметра не допускается. Вызов с unknown остаётся incomplete даже если выбранная подстановка формально удовлетворяет верхней границе unknown.

Существующие metadata `:complete?` и `:source` означают наличие декларации, не решение всех generic-обязательств. `var-type` не должен терять all при попытке вывода через arities. Generic extern использует тот же parse-type, но loader обязан удостовериться, что результат — callable all/fn. Новые generic diagnostics должны быть добавлены в registry подавлений, не переиспользовать exhaustiveness-код.

Вывод в первом ядре использует lower evidence. Только верхняя граница без входного свидетельства оставляет параметр нерешённым (inconclusive), даже когда более мощный solver мог бы подобрать решение. Связанные lower bounds должны распространяться до устойчивого результата независимо от порядка binders; исчерпание бюджета не доказывает совместимость.

Это согласованная граница начального среза. Независимый review может обнаружить дополнительные места интеграции; такие уточнения не расширяют автоматически поддержанный язык.
