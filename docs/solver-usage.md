# Rank-1 solver: первый рабочий срез

Статус: ядро и интеграция проверены общим запуском: 60 тестов / 309 assertions, плюс прежние golden/CLI-проверки. Тело callback проверяется и при недостатке информации о его параметрах. Это не полная реализация generics из feature cards.

## Явная параметрическая функция

```clojure
(defn identity-value
  {:t/sig '(t/all [a] [a :-> a])}
  [x] x)
```

Каждый вызов получает независимые переменные вывода. Тело проверяется для произвольного `a`: замена `x` на `42` нарушает контракт. Имена параметров в эквивалентных декларациях могут различаться.

## Ограниченный параметр

```clojure
(defn numeric-id
  {:t/sig '(t/all [(a :< number?)] [a :-> a])}
  [x] x)
```

Строка не удовлетворяет ограничению. В первом срезе bound — primitive; зависимые и рекурсивные bounds не поддерживаются.

## Callback по ожидаемому типу

```clojure
(defn apply-one
  {:t/sig '(t/all [a b] [a (t/fn [a :-> b]) :-> b])}
  [x f] (f x))

(defn length-of {:t/sig '[string? :-> int?]} [s]
  (apply-one s (fn [text] (count text))))
```

Сначала собираются ограничения обычных аргументов, затем inline `fn` получает типы параметров. Результат callback уточняет `b`. Это ограниченное контекстное выведение, не общий вывод из ожидаемого результата внешнего выражения.

## Extern

```edn
{vendor/id (t/all [a] [a :-> a])}
```

Файл подключается через `:externs` в `typespec.edn`. Если декларация описывает собственную функцию, её тело тоже проверяется. Контракт внешней библиотеки остаётся доверенным.

## Ограничения

Одна фиксированная generic-арность; без rest/kwargs, higher-rank и автоматического let-generalization. Существующая схема сохраняется через локальный alias. Полиморфный callback пока не специализируется автоматически. Вывод основан на нижних ограничениях; только верхняя граница может оставить параметр нерешённым. Неподдержанные структуры и недостаточные сведения дают `TSP210-01`, warning по умолчанию и error в strict. Неудача проверки не считается доказанным контрактом.

Проверки находятся в `solver_test.clj`, `generic_integration_test.clj` и `generic_extern_test.clj`; все подключены к `clojure -M:test`. Эталоны прежних демо для solver не менялись.

## Расширение: refs, карты и macro body contracts

Solver теперь ограниченно раскрывает env specs и проверяет s/keys: обязательные ключи должны присутствовать в source req, поля ковариантны; optional не становится required. Неизвестные ссылки, циклы и предел глубины дают inconclusive. Literal map syntax и generic row polymorphism этим не добавлены.

`:macro-contracts` в typespec.edn позволяет явно доверить схему `{:shape :binding-body :bindings [type ...] :ret type}` qualified non-core макросу. Проверяется первое vector-binding из различных простых символов и оставшееся тело. Без macroexpand/eval; деструктуризация/rest не поддержаны. Некорректная конфигурация — TSP9004, форма вызова — TSP7032. Контракт не устанавливает тип результата macro expression или generated Vars. Пример: examples/context-web-pg/typespec.edn.

Форма `{:shape :malli-defn}` включает проверку объявлений функций с парами `:- schema`. Для приватного варианта добавьте `:private? true`. Типы по-прежнему выводятся из Spec, сигнатур, type hints и тела функции. [Настройка для Metabase](../features/F610-macro-contracts.md)

Общий набор после расширения: 75 тестов / 386 assertions плюс golden/CLI PASS. Web+PG статически: 0 errors/0 warnings, negative fixtures: два TSP2345.

## После независимого review (docs/review-fable-5.2.md)

Исправлено тринадцать находок; подробности и воспроизведения — в самом review. Что изменилось для пользователя:

- `vector?`/`map?` без типа элементов больше не доказывает `(s/coll-of T)`/`(s/map-of K V)` в generic-вызове ни под `s/nilable`, ни в поле карты: будет `TSP210-01`.
- Параметр `(s/nilable a)` работает: `(or-else (:nick u) "anon")` выводит `string?`.
- Аккумуляторы с литеральным seed проверяются без ложной ошибки: `(fold (fn [acc x] (+ acc x)) 0 xs)`. Пустой seed (`[]`) контекста не даёт — вызов «не проверен».
- `#(...)` как callback получает типы параметров так же, как `(fn ...)`.
- Тело `(t/all [a] [a :-> string?])`, возвращающее `x`, — ошибка, а не warning.
- Результат «не проверенного» вызова проверяется дальше, если он известен; кандидат, собранный рядом с unknown-аргументом, как тип не используется.
- Несовпадение числа параметров callback — `TSP2345`.
- `:macro-contracts`: ключ, называющий функцию или форму со встроенным правилом, — `TSP9004`; `_` в binder-векторе может повторяться; неквалифицированное имя совпадает с контрактом только через `:refer` или если макрос объявлен в этом же namespace.
- На один generic-вызов действует лимит раскрытия именованных типов (50000 узлов): сверх него — `TSP210-01` с причиной `size`.

Общий набор: 88 тестов / 471 assertions плюс golden/CLI PASS. Web+PG статически: 0 errors / 0 warnings, negative fixtures: exit 1, два TSP2345.
