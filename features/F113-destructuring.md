# F113 · Деструктуризация

В Clojure параметры функций и `let` часто сразу разбирают входную структуру на локальные имена. Typespec переносит в эти имена типы из Spec и литералов, учитывает type hints и проверяет дальнейшее использование. Обязательность поля следует из типа мапы. Само связывание поля допускает его отсутствие.

## Мапы в Clojure 1.12.4

- `:keys`, `:ns/keys`, `:strs`, `:syms` и `:ns/syms` сохраняют вид и namespace ключа. Явные пары читают keyword, строковый или quoted symbol-ключ. Вложенные patterns получают тип выбранного поля.
- `s/keys` даёт типы keyword-полей, а `s/map-of` даёт тип значения для ключей подходящего вида. Литеральные мапы с такими ключами дают тип поля и факт его наличия. При передаче такой мапы в `s/map-of` проверяются ключи и значения.
- Вычисляемый селектор в форме `{value selector}` проверяется как выражение. Известный строковый, символьный или keyword-ключ читается как явный ключ. Для селектора с подходящим типом ключа `s/map-of` выводится тип значения с учётом возможного отсутствия поля.
- Если Spec или ветки выражения задают конечный набор таких ключей, чекер объединяет типы выбранных полей. `:or` входит в результат, если хотя бы один возможный ключ может отсутствовать. Записанный `nil` сохраняется.
- `:or` применяется при отсутствии ключа, в том числе при разборе `nil`. Присутствующий `nil` остаётся `nil`. Выражение default проверяется и для обязательного поля, а его тип добавляется только при возможном отсутствии поля.
- Для входной мапы `:as` связывает исходное значение. Обычные привязки без default могут участвовать в сужении остальных полей того же union по тесту или `case` на поле-теге.
- При разборе `ISeq` с известными позициями, например из `(list :n 2)`, `(seq [:n 2])` или `'(:n 2)`, пары образуют мапу, которую получает и `:as`. Последний повтор ключа побеждает, в том числе из завершающей мапы с известными ключами. Пустая последовательность даёт пустую мапу, а последовательность из одной мапы или `nil` передаёт её единственный элемент. Внутри `quote` списки и символы типизируются как данные.
- При конечном наборе возможных значений ключа чекер сохраняет возможные формы мапы, включая различия в наличии поля и его перезаписи. Если ключ неизвестен или комбинаций больше 256 для одного набора позиций, результат получает общий тип `map?`.
- Завершающий вектор из двух элементов добавляет пару и может перезаписать ключ, а пустая строка сохраняет собранную мапу. Известный недопустимый хвост, например число, непустая строка или вектор заведомо неверной длины, даёт `TSP2345` на map-шаблоне.
- Завершающая последовательность `Map.Entry` с известными позициями добавляет записи по порядку. `nil` внутри последовательности даёт `TSP2531`, а значение заведомо неверного типа, например число, даёт `TSP2345`.
- Завершающий `seq` структурной мапы добавляет её поля. У открытого `s/keys` обязательные поля перезаписывают значения, опциональные могут их перезаписать, а дополнительные ключи могут изменить тип ранее собранного поля на неизвестный.
- Для хвоста из `s/map-of` или его `seq` ключи, совместимые с контрактом, могут получить значение из хвоста. Перечисление строковых, символьных или keyword-ключей добавляет опциональные поля в пределах 256 ключей. При широком типе ключа собранная мапа сохраняет контракт дополнительных полей. Тип значения учитывается при деструктуризации, чтении через `:as` и проверке вызовов.
- `contains?` с литеральным keyword, строкой или quoted symbol уточняет наличие поля, в том числе полученного из хвоста `s/map-of`. Проверки `some?` и `nil?` сужают значение поля при чтении через `get`, `get-in` или привязанное имя. Ветка `nil?` сохраняет различие между отсутствующим ключом и записанным `nil`.
- `if-some` и `when-some` сужают тип проверенного поля для повторных чтений и связанных имён. Значение `false` попадает в ветку с привязкой, как в Clojure.
- `if-let` и `when-let` учитывают проверку на истинность при повторном чтении поля и использовании связанных имён. В ветке с привязкой исключаются `nil` и `false`.
- Если условная привязка и исходное поле имеют одинаковый тип в ветке, проверка нового имени, например `string?`, уточняет тип исходного поля и связанных с ним имён.
- `assoc` и `dissoc` с quoted symbol обновляют типы полей по точному ключу. Это также учитывается при вызовах функций, которые добавляют или удаляют такие ключи в переданной мапе.
- Символьные литералы в путях `assoc-in` и `update-in` сохраняют соседние поля. `update-in` проверяет функцию по типу предыдущего значения. Для `s/map-of` поддерживаются вычисляемые пути из `s/tuple` с `symbol?`. `select-keys` с точными символьными ключами сохраняет типы выбранных полей.
- `update` со строковым или символьным литералом проверяет функцию по типу предыдущего значения. Если ключ отсутствует, функция получает `nil`. Тип результата обновляет поле в мапе и участвует в проверке контрактов.
- Для вычисляемого ключа `update` сохраняет отдельную форму мапы для каждого ключа из конечного набора. Для `s/map-of` тип ключа и значения из контракта позволяет проверить обновление по вычисляемому keyword, строке или символу.
- `get` с вычисляемым ключом из конечного набора объединяет типы выбранных полей. Умолчание входит в результат, если хотя бы один возможный ключ может отсутствовать. Записанный `nil` сохраняется.
- `dissoc` с вычисляемыми ключами из конечных наборов сохраняет возможные формы мапы. Для каждой комбинации учитывается отсутствие удалённых ключей и сохраняются типы остальных полей.
- `assoc` с вычисляемыми ключами из конечных наборов сохраняет возможные формы мапы и проверяет запись по Spec каждого возможного ключа. Пары применяются слева направо, поэтому последняя запись по ключу побеждает.
- `contains?` с локальным ключом из конечного набора сужает тип ключа и форму мапы в каждой ветке. Если несколько ключей остаются возможными, чекер объединяет варианты в пределах бюджета ветвления.
- `contains?` применяет те же правила напрямую к `s/map-of`. Ветка с ключом сохраняет тип его значения из Spec, а ветка без ключа позволяет использовать умолчание. Типы остальных ключей и значений продолжают участвовать в обходах и обновлениях мапы.
- `some?` и `nil?` сужают чтения напрямую из `s/map-of`, включая вложенный `get-in` и связанные имена. Ветка `nil?` различает отсутствие ключа и записанный `nil`.
- Для сужения по `get` и `get-in` локальный ключ с единственным возможным значением учитывается как точный ключ. Это работает для значения из Spec и для ключа, уточнённого предыдущей проверкой.
- `find` для известного ключа структурной мапы и для `s/map-of` выводит тип записи из ключа и значения. Отсутствующий ключ даёт `nil` и при использовании в хвосте сохраняет ранее собранные поля. Запись со значением `nil` перезаписывает поле.
- Проверка прямого вызова `find` в условии, `some?`, `nil?` или условной привязке уточняет наличие ключа. Найденная запись сохраняет возможность записанного `nil` в значении.
- Проверка результата `find`, сохранённого в локальном имени, уточняет тип записи и наличие ключа в исходной мапе, пока привязки мапы и ключа остаются теми же.
- Проверка `(val entry)` у найденной записи уточняет значение соответствующего ключа в исходной мапе, если ключ известен и привязки остались прежними. При записанном `nil` значение по умолчанию у `get` по-прежнему не применяется.
- Для параметра без контракта `:keys` даёт локальные сведения о читаемых keyword-полях. Типы строковых и символьных полей выводятся из известного входа.
- Порядок именованных привязок и вложенных map- и vector-шаблонов следует развёртке Clojure 1.12.4, когда их формы представлены обычными данными Clojure. Директивы `:keys`, `:strs` и `:syms` сначала расширяются в мапу привязок. `:or` и вычисляемые селекторы видят локальные имена, уже связанные в порядке обхода этой мапы. Директива может заменить селектор явной привязки к тому же имени.

## Пример

```clojure example
(ns example (:require [clojure.spec.alpha :as s]))

(s/fdef item-count :args (s/cat :counts (s/map-of string? int?)) :ret int?)
(defn item-count [{:strs [items] :or {items 0}}]
  (inc items))

(item-count {"items" 2})
(item-count {:items 2})

(let [{n :count :or {n 7}} nil]
  (inc n))

(let [{:syms [count] :or {count 7}} {'count nil}]
  (inc count))
```

```text output
8:13  TSP2345  {:items 2} is not assignable to (s/map-of string? int?)
14:8  TSP2531  count may be nil: count is nil?, and :or applies only when the key is absent
```

Тесты используют обычный `check-files`, проверяют контракт между namespaces, диагностики и исполнение контрольных форм на закреплённом Clojure. [destructuring_test.clj](../test/typespec/destructuring_test.clj)

## Векторы и оставшиеся случаи

Хинт на имени после `:as` в map-деструктуризации проверяется по типу всей мапы. JVM-вызовы через это имя учитывают класс из хинта.

`s/tuple` сохраняет позиции. Для коллекций с ограниченной длиной известные позиции получают тип элемента или `nil` по границам длины. Для обычной коллекции неизвестной длины возможный выход за пределы учитывается с `--strict-nil`. `:as` после `&` сохраняет тип исходного значения. [F330](F330-tuples-and-nonempty.md), [F331](F331-fixed-vector-positions.md)

Для полного статуса карточки остаются вывод формы мапы из последовательностей без известных позиций, порядок связывания для шаблонов с непрозрачными reader-формами и проверка формы на соответствие версии Clojure. Диагностика вложенного отсутствующего поля пока передаёт текстовую причину `nil`. Экспериментальные директивы Clojure 1.13 требуют сверки на отдельно закреплённой версии. [Reference](../docs/reference.md)
