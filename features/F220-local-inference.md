# F220 · Локальный и контекстный вывод типов

Типы из spec, type hints и внешних деклараций используются при выводе локальных значений и проверке тела колбэка. Тип каждого следующего связывания `let` вычисляется в окружении с предыдущими связываниями.

## Колбэки по ожидаемому типу

```clojure example
(ns example.callbacks
  (:require [clojure.spec.alpha :as s]
            [clojure.string :as str]))

(s/def ::on-name (s/fspec :args (s/cat :name string?) :ret string?))
(s/fdef use-name :args (s/cat :f ::on-name) :ret string?)
(defn use-name [f] (f "Ada"))

(use-name #(str/upper-case %))
(let [f (fn [name] (str/upper-case name))]
  (use-name f))
```

```text output
(no diagnostics)
```

Если написать `(str (inc name))`, `TSP2345` укажет на `name` внутри `inc`. Если колбэк возвращает число, чекер выдаст `TSP2345` на аргументе-функции. Проверка использует фактический результат тела, а записи типов параметров содержат источник контекста.

- В обычном вызове сначала выводятся остальные аргументы. Их типы исключают точно несовместимые перегрузки. Контекст колбэка доступен, когда оставшиеся кандидаты согласны по типам параметров. Это работает и когда аргумент, определяющий выбор, стоит после колбэка.
- Для Clojure-функции сначала выбирается подходящая фиксированная арность, затем вариативная. Фиксированные и rest-параметры получают типы из ожидаемых вызовов. Внешний контракт именованного аргумента с литеральным ключом тоже передаёт контекст колбэку.
- `fn`, `#(...)`, их простые локальные aliases и вызовы из `map`, `mapv` и других функций над коллекциями используют ту же проверку. Коллекционные правила проверяют фактически вызываемую арность, а тип элемента результата берут из неё.
- Непосредственный вызов `((fn [x] ...) value)` или `(#(...) value)` передаёт выведенный тип аргумента в тело функции.
- Для inline-функции, связанной в `let`, типы параметров и результата выводятся для каждого различающегося контекста вызова. Например, `(let [add (fn [row] (assoc row :kind :demo))] [(add {:text "hello"}) (add {:num 3})])` сохраняет форму каждой мапы. Тело видит окружение определения. Арности, для которых найден контекст, проверяются с его типами. Остальные арности проходят обычную проверку при выходе из `let`.
- `letfn` связывает все имена перед анализом тел. Типы аргументов передаются и при вызове функции, объявленной ниже в том же `letfn`. При взаимной рекурсии повторный вход использует доступную сигнатуру параметров и консервативный результат.
- При неоднозначном контексте checker выводит тип из самого тела. Недостаток сведений для проверки границы даёт `TSP210-01`. Рекурсивная именованная inline-функция использует ожидаемый контракт. Рекурсивный вывод результата var без контракта завершается с доступным типом, включая `t/unknown`, если вывода недостаточно.

Те же правила работают с `:t/sig` и внешними декларациями. Тест для `pg/fetch` берёт из EDN nullable-строку и индекс. [EDN-декларации context-clj](../examples/context-pg-check/externs.edn)

## Аккумулятор `reduce`

При явном `init` пустая коллекция возвращает `init`. Без `init` пустая коллекция вызывает reducer без аргументов, а один элемент возвращается напрямую. Работающий шаг получает аккумулятор и элемент.

Если шаг может повториться, чекер начинает с типа `init` или элемента и расширяет тип аккумулятора результатом reducer, пока следующий шаг не укладывается в этот тип. Например, `(reduce (fn [acc x] "changed") 0 [1 2])` возвращает строку. Если следующий вызов пытается сложить строковый аккумулятор с числом, ошибка возникает внутри reducer. Для коллекции неизвестной длины тип результата включает достижимые сценарии пустого входа и одного элемента.

Пробные проходы не прибавляют срабатывания директив и не заполняют обычный кеш вывода. Если предел достигнут или результат продолжающегося шага неизвестен, чекер сообщает `TSP210-01` с причиной `:accumulator`.

`reduced` сохраняет тип упакованного значения. `reduce` и `reduce-kv`
используют это значение как результат завершившейся ветки. Эта ветка
не участвует в типе аккумулятора следующего шага. Нульарный вызов
reducer для пустого входа без `init` возвращает результат как есть,
включая `Reduced`. Для известной обёртки `deref` возвращает её значение.

`reduce` выводит тип пары ключ–значение для `s/map-of` и мап с
известными ключами. Для последних он также учитывает число ключей
при выборе между нульарным вызовом reducer и шагом.

Для `(reduce conj [] xs)` тип элементов аккумулятора растёт по тому
же правилу, что и при обычном вызове `conj` на векторе.
Множества и списки также сохраняют тип элементов. Для аккумулятора-мапы
чекер объединяет типы ключей и значений из мап и двухпозиционных
векторов. Например, `(reduce conj {} [[:a 1] [:b 2]])` выводит тип
мапы с ключами `:a`, `:b` и значениями `1`, `2`.
`(reduce into [] chunks)` выводит тип элементов вложенных коллекций.
Для вектора применяется та же проверка источника, что и в `(into [] xs)`.

## Аккумулятор `areduce`

`areduce` проверяет JVM-массив и выводит тип аккумулятора по `init`
и результатам тела на последующих итерациях. Индекс доступен в `init`
со значением `0`, а в теле имеет тип JVM `long`. Например, если шаг
может вернуть строку, следующий `(inc acc)` получает `TSP2345` на
`acc`. Результат включает тип `init`, поскольку массив может быть
пустым. Для известной длины ноль чекер возвращает `init`. Для одного
элемента он проверяет единственный шаг с индексом `0`. Значение
`Reduced` сохраняет тип обёртки.

Если аккумулятор с точно известным классом массива заменяется
ссылкой с более широким JVM-типом, следующий шаг проверяет запись с
учётом ковариантности. При неизвестном результате шага или достижении
предела вывода чекер выдаёт `TSP210-01` с причиной `:accumulator`.

## Границы

- Вывод из всех мест вызова, полиморфизм локальных функций и общее возобновление зависимых ограничений относятся к F230 и F231. [F230](F230-generics-and-hof.md) · [F231](F231-generic-obligations.md)
- Именованные аргументы поддерживают устойчивый литеральный ключ внешнего вызова. Совместимость самих функций с keyword-rest контрактами относится к F410. [F410](F410-arities-and-apply.md)
- `filter some?` сохраняет исходный тип элемента до появления вывода предикатных фактов. Вызов `map` без коллекции даёт `t/unknown` для трансдьюсера. [F250](F250-checked-guards.md) · [F230](F230-generics-and-hof.md)
