# F240 · Сужение, tagged unions и полнота веток

Проверки в обычном Clojure-коде уточняют типы в ветках. Для событий, команд и состояний тип остальных полей следует из значения тега. Описание вариантов можно взять из `s/def`, `s/keys` и `s/or`, а контракт функции — из `s/fdef`. Те же правила работают с типом, выведенным из выражения, type hint или внешней декларации.

## Мапы с тегом

```clojure example
(ns example.events
  (:require [clojure.spec.alpha :as s]
            [clojure.string :as str]))

(s/def :text/kind #{:text})
(s/def :text/payload string?)
(s/def :count/kind #{:count})
(s/def :count/payload int?)
(s/def ::text (s/keys :req-un [:text/kind :text/payload]))
(s/def ::count (s/keys :req-un [:count/kind :count/payload]))
(s/def ::event (s/or :string ::text :number ::count))
(s/fdef render-event :args (s/cat :event ::event) :ret string?)

(defn render-event [{:keys [kind payload]}]
  (case kind
    :text  (str/upper-case payload)
    :count (str (inc payload))))
```

```text output
(no diagnostics)
```

`inc` в ветке `:text` даёт `TSP2345`. Если добавить вариант с тегом `:reset`, пропущенная ветка даёт `TSP8001`. Теги берутся из поля `:kind`. Метки `s/or` именуют альтернативы spec.

Чекер сохраняет связь целых вариантов мапы с полями. Вложенный путь можно записать как `(:kind (:meta event))`, `(get-in event [:meta :kind])` или связать через обычный `let` и деструктуризацию. Если один тег соответствует нескольким вариантам, ветка получает их объединение. Для закрытой диспетчеризации все ключи пути должны быть обязательными, а домен тега конечным.

## Условия и полнота

| Форма | Что выводит чекер |
|---|---|
| `if`, `when`, `cond` | Равенство с литералом уточняет совпавшие варианты в истинной ветке и оставшиеся варианты в ложной |
| `some?`, `nil?`, встроенные предикаты, `instance?`, `s/valid?` | Уточняют локальный тип по гарантиям предиката. Ложная ветка исключает только доказанно совпадающие варианты |
| `contains?` | Уточняет присутствие объявленного ключа. Тип присутствующего значения сохраняет `nil`, если он разрешён spec |
| `not`, `and`, `or` | Учитывают отрицание, короткое замыкание и объединение путей |
| `case` | Проверяет пропущенные и невозможные метки в закрытом домене. Default получает остаток |
| `condp =` | Уточняет тип по литеральным меткам и в default. В закрытом домене пропущенная ветка без default даёт `TSP8001` |

Например, после `(= :text (:kind event))` истинная ветка получает строковый payload, ложная — числовой. Цепочка `cond` передаёт ложную ветку следующей проверке. Если все варианты обработаны, результат не содержит `nil` от прохода мимо всех веток. При достижимом проходе мимо всех веток `cond` возвращает `nil`, как в Clojure.

Условия можно сохранить в локальном значении, например `(let [present (some? x)] (if present ...))`. Факт применим, пока использованные в проверке символы ссылаются на те же связывания. Снимок `(let [x @state] ...)` можно сужать по `x`. Повторное `@state` остаётся отдельным чтением.

Сравнения `=` и `not=` между встроенным `count` и целым литералом
уточняют границы длины в обеих ветках. Для группы длиной 1–2 проверка
`(= 1 (count pair))` оставляет ровно два элемента в `else`. Проверка
`pg --accept` закрепляет этот факт в трёх SQL-обработчиках.

Для `case` числовые теги участвуют в доказательстве полноты в режиме целочисленной диспетчеризации в диапазоне 32 бит. В режиме диспетчеризации по хешу равные числа разных JVM-представлений могут попадать в разные ветки. `if`, `cond` и `condp =` используют семантику обычного `=`.

## Границы

- Сужение через поля применяется к устойчивым путям из литеральных ключей. Вычисляемый ключ, неизвестная форма мапы или исчерпанный лимит раскрытия сохраняют исходные типы.
- `false` и `nil` выбирают ложную ветку обычного условия. `some?` исключает только `nil`.
- Контракты пользовательских предикатов описаны в [F250](F250-checked-guards.md), общий анализ выхода из выражения — в [F420](F420-control-flow.md), диспетчеризация мультиметодов — в [F440](F440-multimethods.md).

Регрессии покрывают прямые и вложенные теги, деструктуризацию, остаток в `cond` и `condp`, необязательные и nullable-поля, общие теги нескольких вариантов и shadowing. [Тесты](../test/typespec/case_narrowing_test.clj)
