# F271 · Mapped types: преобразование полей типа

## Мотивация и приоритет

Обобщить конечные Pick/Omit/Partial, если реальные Clojure-задачи потребуют собственного преобразования формы. Не условие MVP.

## Пример целевого поведения

```clojure
;; Цель: из типа {:id int?, :name string?}
;; получить форму patch с теми же типами, но optional-полями.
;; Базовый случай уже покрывает (t/partial T) из F270.
;; Синтаксис общего mapped type пока НЕ утверждён.
```

Иллюстрация, не исполняемый тест и не утверждение о текущей реализации.

## Алгоритм и границы

1. Начать с конечных известных ключей мапы.
2. Связать переменную ключа с каждым литералом и вычислить тип поля по ограниченной грамматике.
3. Явно передавать required/optional, не смешивать optional и nilable.
4. Проверять коллизии при переименовании ключей и ограничивать размер результата.
5. Неизвестные ключи, рекурсию и превышение бюджета отмечать как неподдержанное; не получать успешный unknown.
Это исследовательский эскиз. Начинать реализацию только при сценарии, который не решается F270.

## Критерии готовности и тесты

Сохранение типов полей, optional без лишнего nil, коллизии ключей, union-вход и остановка по лимиту.
