# F330 · Длина и непустые коллекции

Длина берётся из литералов, `s/tuple` и `s/coll-of`. Обычный
`typespec check` учитывает `:min-count` и `:max-count` при передаче
аргументов и проверке возвращаемого значения. Для `:kind vector?` и
`:kind set?` опция `:count` задаёт точную длину. Для последовательности
без гарантии `counted?` из `:count` следует нижняя граница, как
в проверке через `bounded-count` в Clojure Spec.

`(partition-all n coll)` и `(partition-all n step coll)` возвращают
последовательность групп, каждая из которых сохраняет тип элемента входа.
При известном положительном целом `n` размер группы составляет от одного
до `n` с учётом длины исходной коллекции. Известные длина входа и
положительный целый шаг дают границы числа групп. `pg --accept` проверяет
типы трёх вызовов `(partition-all 2 pairs)` в SQL-обработчиках.

`(interpose separator coll)` сохраняет тип элементов и добавляет тип
разделителя, если во входе может быть два элемента или больше. Пустой
вход даёт пустую последовательность. При известной ненулевой длине `n`
длина результата составляет `2*n - 1`. Проверка `http --accept` закрепляет
тип последовательности в `breadcrumb`.

`concat` объединяет типы элементов и складывает границы длины аргументов.
`nil` и заведомо пустые коллекции дают ноль элементов. Верхняя граница
сохраняется, когда она известна для всех аргументов. Проверка `pg --accept`
закрепляет минимальную длину в `join-vec` и SQL-обработчиках.

Двухаргументный `into` с вектором назначения складывает границы длины
вектора и источника. Проверка `pg` закрепляет вывод длины после
`(into [] (concat ...))` при сборке SQL-фрагментов.

`vec` сохраняет границы длины и типы известных позиций. Проверка `pg`
закрепляет перенос границ через `drop-last` и `vec` по образцу `:pg/coalesce`.

`group-by` выводит `s/map-of`, где каждая существующая группа имеет тип
`(s/coll-of T :kind vector? :min-count 1)`. Чтение группы по ключу
учитывает возможное отсутствие ключа. Пустой вход даёт пустую карту.
Проверка `get-ig` закрепляет тип групп в `reindex-tgz`.

`sort` и `sort-by` сохраняют тип элементов и границы длины при перестановке,
в том числе при явном компараторе. Для `nil` и пустых коллекций результат
имеет длину ноль. Проверка `http --accept` закрепляет границы из Spec
при сортировке MCP-инструментов, а `get-ig` проверяет тип результата `semver/latest`.

`reverse` сохраняет тип элементов и границы длины. Если позиции входа
известны, их типы переносятся в обратном порядке. Проверка `get-ig`
закрепляет длину после `reverse` поверх сортировки версий.

`drop-last` вычитает из границ длины известное целое число элементов
и сохраняет позиции оставшегося префикса. В форме с одной коллекцией
убирается один элемент. Если размер удаления неизвестен, сохраняется
верхняя граница исходной длины.

`map` и `mapv` сохраняют длину одной коллекции. При нескольких коллекциях
длина результата ограничена самой короткой. Проверка `get-ig` закрепляет
границы из Spec для `(mapv :name packages)`. В `http` проверяется цепочка
`map` и `sort-by` при подготовке списка MCP-инструментов.

`map-indexed` сохраняет границы длины с входа. Проверка `http --accept`
передаёт их через `map-indexed` и `interpose` в примере по образцу `breadcrumb`.

`filter`, `filterv` и `remove` сохраняют верхнюю границу длины. Результат
может быть пустым даже при непустом входе. Проверки `pg` и `http` закрепляют
эту гарантию при выборе миграций, путей и частей квалифицированного имени.

```clojure example
(ns example (:require [clojure.spec.alpha :as s] [clojure.string :as str]))

(s/fdef label :args (s/cat :xs (s/coll-of string? :kind vector? :min-count 1)) :ret string?)
(defn label [xs] (first xs))

(label ["ready"])
(label [])

(s/fdef guarded :args (s/cat :xs (s/coll-of string? :kind vector?)) :ret (s/nilable string?))
(defn guarded [xs]
  (when-let [items (seq xs)]
    (str/upper-case (first items))))
```

```text output
7:8  TSP330-01  expected collection length at least 1, got 0
```

В ветке успеха `(seq xs)` длина исходного устойчивого значения и
результата составляет минимум один элемент. Если элемент может
быть `nil`, `first` сохраняет этот вариант. `rest` может вернуть
пустую последовательность. `next` и остаток в `& tail` при
исчерпанном входе возвращают `nil`. Деструктуризация по отсутствующей
позиции связывает `nil`.

`nth` и числовой шаг `get-in` используют известные границы. Default
добавляется для отсутствующей позиции и сохраняется отдельно от
допустимого значения `nil`. Для `nth` без default доказанный выход
за границу даёт `TSP330-02`. `apply` проверяет фиксированные позиции
tuple и однородные хвосты известной длины до 64 элементов.

`=` и `not=` сравнивают `count` с целым литералом и уточняют границы
длины. Неравенство сохраняет оба оставшихся диапазона, если исключённое
значение лежит внутри интервала. Вычисляемые индексы и сравнения порядка
с `count` остаются в плане.
Операции с неподтверждённым изменением длины сбрасывают её ограничения.
