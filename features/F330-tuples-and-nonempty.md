# F330 · Длина и непустые коллекции

Длина берётся из литералов, `s/tuple` и `s/coll-of`. Обычный
`typespec check` учитывает `:min-count` и `:max-count` при передаче
аргументов и проверке возвращаемого значения. Для `:kind vector?` и
`:kind set?` опция `:count` задаёт точную длину. Для последовательности
без гарантии `counted?` из `:count` следует нижняя граница, как
в проверке через `bounded-count` в Clojure Spec.

Успешное чтение `(get-in v [i])` по точному индексу доказывает длину
вектора не меньше `i + 1`. Проверка на `nil` даёт верхнюю границу `i`,
если элементы вектора по контракту не могут быть `nil`.
`(contains? v i)` с известным целым индексом уточняет обе границы
длины по веткам. Тип элемента сохраняется, в том числе возможный `nil`.

Для JVM-массивов точная длина выводится из известного размера
конструктора или длины входной последовательности. `aclone` и `amap`
сохраняют длину внешнего массива. `alength` возвращает литеральный тип,
когда длина известна, и `int?` при неизвестной длине. Объединение
массивов одного класса сохраняет длину, если все ветки сообщают
одинаковый размер. `areduce` использует известные размеры `0` и `1`
для проверки только достижимых итераций.

`seq`, `next`, `rest` и позиционные чтения массива сохраняют известную
длину и тип компонента. Элемент ссылочного массива может быть `nil` даже
на заведомо существующей позиции. Для элементов платформенного массива
из Java возможный `nil` в последовательности проверяется с
`--strict-nil`.

`aget`, `aset` и примитивные `aset-*` проверяют известные индексы
после преобразования Clojure в JVM `int`. Например, `1.9` обращается
к элементу `1`, а индекс `2` в массиве длины `2` даёт `TSP330-02`.
Отрицательный индекс отклоняется и при неизвестной длине JVM-массива.
Многоиндексный вызов проверяет каждое измерение, для которого известна
длина. При гарантированном выходе за границы дальнейшие измерения
недостижимы. Для переполнения в библиотечном преобразовании используется
тот же код. Переполнение при встраиваемой арности зависит от
`*unchecked-math*` в месте вызова.

`(partition-all n coll)` и `(partition-all n step coll)` возвращают
последовательность групп, каждая из которых сохраняет тип элемента входа.
При известном положительном целом `n` размер группы составляет от одного
до `n` с учётом длины исходной коллекции. Известные длина входа и
положительный целый шаг дают границы числа групп. `pg --accept` проверяет
типы трёх вызовов `(partition-all 2 pairs)` в SQL-обработчиках.
В трёхаргументном `into` трансдьюсер `(partition-all n)` выдаёт
непустые векторы с типом элемента источника. Длину группы ограничивают
известная положительная ёмкость и верхняя граница длины входа.
При положительной ёмкости число групп ограничено результатом деления
верхней границы входа на ёмкость с округлением вверх. Нулевая ёмкость
даёт не больше одной группы.

`(partition-by f coll)` передаёт тип элемента в функцию ключа и
возвращает ленивую последовательность непустых групп с тем же типом
элемента. Непустой источник гарантирует хотя бы одну группу. Верхняя
граница длины источника ограничивает и размер группы, и их число.

`(interpose separator coll)` сохраняет тип элементов и добавляет тип
разделителя, если во входе может быть два элемента или больше. Пустой
вход даёт пустую последовательность. При известной ненулевой длине `n`
длина результата составляет `2*n - 1`. Проверка `http --accept` закрепляет
тип последовательности в `breadcrumb`.

`concat` объединяет типы элементов и складывает границы длины аргументов.
`flatten` выводит тип листьев из вложенных последовательных коллекций и
сохраняет границы длины, когда они известны. Мапы, множества и строки
сохраняются как элементы внутри последовательности. Такой аргумент
верхнего уровня даёт пустую последовательность. Для непрозрачных
веток остаётся неизвестный тип элемента.
`nil` и заведомо пустые коллекции дают ноль элементов. Верхняя граница
сохраняется, когда она известна для всех аргументов. Проверка `pg --accept`
закрепляет минимальную длину в `join-vec` и SQL-обработчиках.

Двухаргументный `into` с вектором назначения складывает границы длины
вектора и источника. Проверка `pg` закрепляет вывод длины после
`(into [] (concat ...))` при сборке SQL-фрагментов.

Трёхаргументный `into` с поддержанным трансдьюсером сохраняет нижнюю
границу длины вектора, множества или последовательности назначения.
Верхняя граница складывает максимальный размер назначения и максимальное
число элементов из трансдьюсера. Для множества сумма даёт верхнюю оценку,
поскольку повторы могут уменьшить число добавленных элементов.

`seq`, `next` и `rest` принимают по одному аргументу. Известный скаляр,
который JVM не может превратить в последовательность, даёт `TSP2345`.
`nil` допустим. Чекер сохраняет типы позиций и границы длины хвоста.
Для строкового литерала `seq`, `next`, `rest`, `first` и `second`
используют длину в единицах UTF-16. Известная позиция даёт
`java.lang.Character`, пустой вход или отсутствующая позиция дают `nil`
там, где его возвращает Clojure.

`vec` сохраняет границы длины и типы известных позиций. Проверка `pg`
закрепляет перенос границ через `drop-last` и `vec` по образцу `:pg/coalesce`.

`conj` с вектором увеличивает обе известные границы длины на число
добавленных элементов и сохраняет известные позиции. Проверка `pg`
закрепляет полный вывод через `drop-last`, `vec` и `conj`.
При росте вектора в `loop` и `reduce` чекер обобщает длину аккумулятора
и сохраняет типы его элементов.

`pop` вычитает один элемент из границ длины вектора и сохраняет типы
позиций оставшегося префикса. Заведомо пустая ветка даёт `TSP330-02`.
Проверка `pg` закрепляет этот вывод после удаления SQL-разделителя.

`peek` читает тип последней известной позиции вектора. Для однородного
вектора используется тип элемента, а возможный пустой вход добавляет `nil`.
Проверка `pg` закрепляет тип последнего SQL-фрагмента.

`last` использует тип последней известной позиции последовательности
или тип её элемента. Гарантия непустого входа из Spec позволяет
вернуть этот тип при `--strict-nil`. Проверка `get-ig` закрепляет
этот случай после сортировки версий.

`first` и `second` проверяют тип и число аргументов при прямом вызове и
как колбэки. Результат следует из типа позиции и границ длины.
Например, `(map first)` после
`(partition-all 2)` возвращает тип элемента группы, а `(map second)`
учитывает `nil` в последней группе длины один.
Условие на результат `first` или `second` уточняет длину исходного
вектора или последовательности. Проверка значения, полученного
деструктуризацией, учитывает тот же номер позиции.

Для мапы с известным набором ключей и `s/map-of` чтение
последовательности сохраняет тип ключа и значения в записи `MapEntry`.
`key` и `val` извлекают соответствующие типы. Для мапы с несколькими
записями чекер объединяет возможные записи без предположений о порядке.

`group-by` выводит `s/map-of`, где каждая существующая группа имеет тип
`(s/coll-of T :kind vector? :min-count 1)`. Чтение группы по ключу
учитывает возможное отсутствие ключа. Пустой вход даёт пустую карту.
Проверка `get-ig` закрепляет тип групп в `reindex-tgz`.

`reduce` использует нижнюю и верхнюю границы длины из вывода или Spec.
Для непустой группы `group-by` редьюсер без начального значения
проверяется только на вызов с аккумулятором и очередным элементом.
При длине 1 результат берётся из единственного элемента.
Нулевая арность редьюсера проверяется, когда вход может быть пустым.

`sort` и `sort-by` сохраняют тип элементов и границы длины при перестановке,
в том числе при явном компараторе. Для `nil` и пустых коллекций результат
имеет длину ноль. Проверка `http --accept` закрепляет границы из Spec
при сортировке MCP-инструментов, а `get-ig` проверяет тип результата `semver/latest`.

`reverse` сохраняет тип элементов и границы длины. Если позиции входа
известны, их типы переносятся в обратном порядке. Проверка `get-ig`
закрепляет длину после `reverse` поверх сортировки версий.

`take` ограничивает обе границы длины известным числом элементов
и сохраняет типы позиций префикса. `take 0` возвращает пустую
последовательность без чтения элементов входа.

`drop-last` вычитает из границ длины известное целое число элементов
и сохраняет позиции оставшегося префикса. В форме с одной коллекцией
убирается один элемент. Если размер удаления неизвестен, сохраняется
верхняя граница исходной длины.

`butlast` оставляет префикс со сдвинутыми границами длины. Вход из нуля
или одного элемента даёт `nil`. Проверка `http` закрепляет границы после
`(into [] (butlast path))` на примере роутинга.

`map`, `mapv` и `pmap` сохраняют длину одной коллекции. При нескольких коллекциях
длина результата ограничена самой короткой. Проверка `get-ig` закрепляет
границы из Spec для `(mapv :name packages)`. В `http` проверяется цепочка
`map` и `sort-by` при подготовке списка MCP-инструментов.

`map-indexed` сохраняет границы длины с входа. Проверка `http --accept`
передаёт их через `map-indexed` и `interpose` в примере по образцу `breadcrumb`.

`doall` сохраняет тип исходной коллекции, включая границы и позиции.
В `(doall n xs)` число `n` ограничивает вычисление, а возвращается весь
`xs`. Проверка get-ig покрывает цепочку `pmap` → `doall`.

`filter`, `filterv` и `remove` сохраняют верхнюю границу длины. Результат
может быть пустым даже при непустом входе. Проверки `pg` и `http` закрепляют
эту гарантию при выборе миграций, путей и частей квалифицированного имени.

```clojure example
(ns example (:require [clojure.spec.alpha :as s] [clojure.string :as str]))

(s/fdef label :args (s/cat :xs (s/coll-of string? :kind vector? :min-count 1)) :ret string?)
(defn label [xs] (first xs))

(label ["ready"])
(label [])

(s/fdef guarded :args (s/cat :xs (s/coll-of string? :kind vector?)) :ret (s/nilable string?))
(defn guarded [xs]
  (when-let [items (seq xs)]
    (str/upper-case (first items))))
```

```text output
7:8  TSP330-01  expected collection length at least 1, got 0
```

В ветке успеха `(seq xs)` длина исходного устойчивого значения и
результата составляет минимум один элемент. Если элемент может
быть `nil`, `first` сохраняет этот вариант. `rest` может вернуть
пустую последовательность. `next` и остаток в `& tail` при
исчерпанном входе возвращают `nil`. Деструктуризация по отсутствующей
позиции связывает `nil`.

`nth` и числовой шаг `get-in` используют известные границы. `nth` по
конечному множеству индексов из Spec или веток выражения объединяет типы
только возможных позиций. Default добавляется для отсутствующей позиции
и сохраняется отдельно от
допустимого значения `nil`. Для `nth` без default доказанный выход
за границу даёт `TSP330-02`. `apply` проверяет фиксированные позиции
tuple и однородные хвосты известной длины до 64 элементов.
Для хвоста неизвестной длины `apply` использует единственную variadic
сигнатуру, если явные аргументы закрывают её минимальную арность,
а хвост гарантированно поддерживает `seq`. Тип каждого элемента хвоста
проверяется по rest-параметру.

`empty?` уточняет коллекцию до пустой или непустой в зависимости от ветки.
`nil` возможен только в ветке для пустого входа, а `first` в непустой
ветке сохраняет nullable-элемент, если его допускает Spec.

`=`, `not=`, `<`, `<=`, `>` и `>=` сравнивают `count` с целым литералом
и уточняют границы длины в обеих ветках. `not=` сохраняет оба оставшихся
диапазона, если исключённое значение лежит внутри интервала. Например,
ложная ветка `(< (count pair) 2)` содержит хотя бы два элемента.
Операции с неподтверждённым изменением длины сбрасывают её ограничения.
