# F412 · Арности из `s/+` и конечных `s/alt`

`s/fdef` и `s/fspec` читают позиционные аргументы из Clojure Spec.
Повторение `s/+` требует хотя бы один аргумент, `s/*` допускает ноль.
Конечный `s/alt` описывает альтернативные списки аргументов, включая
ветви с однородным variadic-хвостом. Правила
работают внутри `s/cat`, при прямых вызовах и при `apply` с хвостом
известной длины. `partial` вычитает уже переданные аргументы из минимума.

```clojure example
(ns example (:require [clojure.spec.alpha :as s]))

(s/fdef total :args (s/cat :items (s/+ int?)) :ret int?)
(defn total [& xs] (reduce + xs))

(s/fdef label :args (s/alt :id int? :pair (s/cat :id int? :name string?)) :ret string?)
(defn label ([id] (str id)) ([id name] (str id " " name)))

(total 1)
(apply total [])
(label 1 "name")
(label "name")
```

```text output
10:1  TSP2554  apply total expects 1+ argument(s), got 0
12:8  TSP2345  "name" is not assignable to int?
```

Конечные ветви могут комбинировать `s/cat`, `s/alt` и `s/?`.
Обёртка `s/with-gen` вокруг всей формы или отдельной ветки сохраняет арности
и типы аргументов. Checker не вызывает генератор.
`s/spec` и `s/nonconforming` также сохраняют арности, когда оборачивают весь
`:args`. Внутри `s/cat` обёрнутый regex с конечным числом позиций описывает
один последовательный аргумент. Проверяются типы и длина известного вектора
или списка, а параметры доступны при деструктуризации. `nil` допустим, если
regex принимает пустой вход. `sequential?` сам по себе не гарантирует `count`.
`s/?` сохраняет пропуск аргументов и допустимые арности своей ветви,
в том числе минимальную длину её variadic-хвоста.
Однородный `s/*` или `s/+` поддерживается в конце списка.
Именованные regex из `s/def` раскрываются в `:args` и внутри `s/cat`
с учётом namespace объявления. Обычный именованный предикат по-прежнему
проверяет одно значение внутри `s/cat`. Самостоятельное использование
regex в качестве типа значения пока даёт `TSP9002` на его объявлении.
Для `s/&` checker сохраняет типы и арности первого операнда.
Предикаты над conformed-аргументами получают `TSP9002`.
Завершающий `s/keys*` проверяет пары ключей и значений, например
`(s/cat :host string? :opts (s/keys* :req-un [::timeout]))`.
В функции с единственной вариативной реализацией и маповой деструктуризацией
эти типы также участвуют в выводе результата при отсутствующем `:ret`.
Для литеральных ключей и вычисляемых ключей с конечным набором
значений проверяются обязательность, типы и точные namespace
ключей. Последнее значение повторённого ключа побеждает, в том числе
при повторении одного локального имени. Один
завершающий аргумент-мапа не входит в этот Spec. При известной
позиционной длине правило также применяется к `apply`.
Раскрытие ограничено 64 различными ветвями и 256 переходами по ссылкам.
Для неподдержанного regex, включая рекурсию и повторение в середине
списка, checker выдаёт `TSP9002`.

Одно тело Clojure может обслуживать несколько альтернатив. Checker
объединяет типы соответствующих позиций при проверке тела. Связи между
разными позициями из одной альтернативы при этом не сохраняются.
