# F721 · Var и его корневое значение

Чекер собирает имена из `def` внутри функций и поддерживаемых форм
кода. Такое объявление создаёт Var при компиляции формы. Корневое
значение появляется, когда выполнится инициализатор.

```clojure example
(ns example)

(defn initialize! []
  (def context :ready)
  context)

#'context

(declare settings)
(do
  (def settings nil)
  settings)
```

```text output
(no diagnostics)
```

И `#'context`, и `(var context)` имеют тип `clojure.lang.Var`.
При прямом чтении `context` без доказанной инициализации чекер
выдаёт `TSP721-01` и выводит `t/unknown`. В обычном режиме это
предупреждение, в `--strict` ошибка. `TSP2305` применяется к
неизвестному имени в известном namespace. `(def settings nil)`
инициализирует Var, тогда как `(def settings)` и `declare` только
объявляют имя.

В формах `#'` и `var` доступны приватные Var из закреплённого
каталога стандартной библиотеки. Прямое чтение такого имени из
другого namespace даёт `TSP2305`.

У `def` и `defonce` checker проверяет известный тип инициализатора
по хинту на имени. Несовместимый тип даёт `TSP2322` на хинте.
Если у Var один известный инициализатор с хинтом, его тип участвует
в проверке чтения, в том числе из другого namespace. Проверка
инициализации сохраняется.

Regex-литерал в единственном корневом `def` или `defonce` даёт тип
`Pattern` для потребителей из других namespace. Динамические Var,
известные записи через вложенный `def` и `alter-var-root`, а также чтение
внутри `with-redefs` сохраняют неполноту проверки.
Встроенный `re-pattern` в стабильном инициализаторе также даёт `Pattern`.
Для известной строки сохраняется число групп.

Скалярный литерал в единственном инициализаторе `^:const` даёт тип
значения напрямую. Строка, число, keyword, boolean, знак `Character`
и `nil` проверяются у потребителей с учётом этого типа.
Литеральные мапы, векторы и множества также сохраняют форму и типы
элементов. Вложенные вызовы в инициализаторе остаются за рамками
литерального вывода.

Прямой `def` в последовательности доказывает инициализацию для
следующих выражений этой последовательности. На верхнем уровне
учитывается порядок форм в файле, включая `do`. Для функций и
потребителей из других namespace чекер учитывает прямые
инициализаторы после успешной загрузки namespace. Вызов отдельной
функции-инициализатора сам по себе не добавляет доказательство.

Объявления `defn` внутри верхнеуровневых `let` и `do`
входят в индекс namespace. При проверке тела и выводе возвращаемого
типа учитываются захваченные локальные значения. Потребители из
других namespace видят арность и контракт функции.

Сбор поддерживает `def` внутри `defn`, `fn`, `let`, `do`, веток
и других известных форм. Цитаты, `comment` и непрозрачные вызовы
макросов не участвуют в сборе. Вложенные `declare` и `defonce`
учитываются при явном обращении к `clojure.core`. В неописанной
форме с вектором простых имён на первой позиции эти имена могут
оказаться локальными binding. Чекер сохраняет неполноту для
неуточнённых чтений. Явно квалифицированные обращения остаются
чтениями Var.

В get-ig `fhir.registry/context` на верхнем уровне `diff.clj`
получает `TSP721-01`. Порядок запуска приложения и динамические
перепривязки остаются отдельной задачей.
