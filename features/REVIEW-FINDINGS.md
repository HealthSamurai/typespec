# Находки при сведении карточек

Редакционное сведение завершено: получены 40 карточек с примерами и алгоритмами. Ниже — конкретные результаты выборочной технической проверки, не доказательство корректности всех алгоритмов.

## Подтверждено точечным запуском родителя

### F113/F310: default при деструктуризации и get расходятся

Проверка через `main/run-check` с OpenJDK 25:

```clojure
(s/def :account/retries (s/nilable int?))
(s/def ::job (s/keys :opt [:account/retries]))

(defn next-attempt
  {:t/sig '[::job :-> int?]}
  [{:account/keys [retries] :or {retries 0}}]
  (inc retries))

(defn attempts
  {:t/sig '[::job :-> int?]}
  [job]
  (get job :account/retries 0))
```

Получена одна диагностика TSP2531 для `inc retries`; вторая функция принята без ошибки. Значит карточки верно описывают дефект get/default: default не должен убирать nil, присутствующий в значении. Исходники checker не исправлялись в рамках ревью.

## Подтверждено целевыми проверками авторов

- F210: unknown→string и unknown→never допускаются текущим subtype?; это не безопасная семантика unknown. Автор выполнил тест с установленным JDK.
- F830: текущий ignore подавляет шире одного кода; пустая/пробельная причина принимается. Неиспользованное подавление даёт TSP2578. Это отличается от проектируемой адресной фильтрации.
- F150: автор исправил положение attr-map и перенёс проверяемые вызовы внутрь defn, затем подтвердил ошибки тела и отсутствующего ключа целевым запуском.

## Согласованные границы

- F115 различает реально работающий путь t/sig и будущую полную валидацию грамматики/арностей.
- F510/F520 отделяют чтение JVM-контракта от применимости вызова: varargs и выбор перегрузки нельзя считать проверенными лишь по наличию reflection-данных.
- F130/F710 должны сохранять доступное собственное тело при добавлении внешней аннотации; сторонние контракты остаются доверенными. Версия и источник обязательны для воспроизводимости.

## Исправление условий запуска

Сообщения части авторов об отсутствии Java были неточны. JDK установлен: `JAVA_HOME=/opt/homebrew/opt/openjdk@25`, его bin нужно добавить в PATH. Авторам отправлены уточнения; в карточках следует говорить о неудачном первоначальном окружении, а не об отсутствии JVM.

## Ещё требуется

Следующий этап — индекс и тесты. Полная реализация и исполнение всех 200 примеров остаются будущей работой; иллюстративные блоки тестовый раннер не проверяет.

## Дополнительные подтверждения авторов

- F810: проверены пять примеров; неподдержанный макрос даёт TSP7031, вложенное выражение не посещается. Это подтверждает необходимость независимого знаменателя покрытия.
- F910: smoke test подтвердил повторяющийся id у двух reflection-диагностик. Нельзя использовать нынешний id как уникальный ключ записи в UI или baseline без дополнительной информации.
- F350: runtime smoke подтвердил сохранение record при assoc и потерю record при dissoc объявленного поля. Это тест семантики Clojure, не реализованной проверки Typespec.
- F720: контракт инкрементального теста сформулирован правильно — результат тёплой проверки сравнивается с чистой после той же правки; список пересчитанных ns проверяется отдельно. Interface hash не заменяет fingerprint тела и настроек диагностик.

## Рекурсия и единая граница безопасности

Автор F295 подтвердил точечным тестом: string <: number отвергается, но те же несовместимые листья под 20 вложенными vector-coll принимаются из-за depth cutoff. Это самостоятельная причина ложного успеха помимо permissive unknown. Алгоритмы F230/F290/F340/F295 должны опираться на результат «доказано / опровергнуто / не удалось проверить», а не трактовать нынешний boolean sub? как доказательство.

F290 корректно отделяет brand от validated-spec: обычный predicate не создаёт brand; аннотация результата конструктора не освобождает от проверки тела. F410 отделяет проверку прямой арности от apply; неизвестная длина аргументов не превращается в доказанный успешный вызов. Эти границы согласуются с F210 и F260.

## Итог сведения

- 40 карточек, 200 блоков Clojure; все карточки имеют по пять примеров.
- YAML: 21 partial и 19 not-implemented. Никто не объявлен implemented только за написанный алгоритм.
- Проверены совпадение ID/имени, парность fences и существование локальных ссылок: ошибок нет.
- F240 сохраняет границу между текущим сужением локальных значений и будущей корреляцией tagged maps; метки s/or не считаются полями runtime-значения. Это согласуется с F112/F250/F340.
- Требование отдельных файлов для core и библиотек включено в F130/F710; загрузка ещё не реализована.
- arXiv-отчёт находится в ../docs/arxiv-typechecking.md. Он поддерживает направление optional static checking, но основан преимущественно на abstracts; это не верификация алгоритмов карточек.

Ревью было редакционным и выборочным техническим: проверены структура, статусы и ключевые пересечения. Формальные доказательства, все возможные входы и все примеры не проверялись. Изменения checker в ходе этой стадии не вносились.
